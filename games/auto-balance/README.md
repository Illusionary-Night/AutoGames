# 流動平衡

- **來源點子**：ideas/seeds/auto-balance.md
- **目前版本**：v2（尚未發佈給測試者，尚無任何人類評分）
- **狀態**：實驗中
- **題材**：抽象對戰
- **核心機制**：自動平衡（倍率隨勝負調整）、三戰線配對、屬性剋制
- **玩法摘要**：每回合從 6 個單位中選 3 個，分三條戰線和電腦對戰。每個單位有隨勝負自動調整的倍率，贏的被削弱、輸的與沒出場的被加強，所以沒有固定最佳組合，要讀倍率變化選組合。
- **面向自由度**：沿用來源點子（玩法 partial，其餘 free）

## 版本紀錄

### v1

- **改了什麼**：第一版。
- **假設**：只靠公開的倍率變化，能不能讓玩家自然產生「這回合該換什麼組合」的思考。
- **本機模擬結果（20000 場，電腦對手雜訊 0.5–1.5）**：
  - 固定同一組合：勝率約 35%，敗率約 44%
  - 隨機選：勝率約 21%，敗率約 64%
  - 每回合選有效強度最高的 3 個：勝率約 63%，敗率約 20%
  - 每回合選有效強度最低的 3 個：勝率約 2%
  - 解讀：固定組合會被平衡機制壓制，會讀倍率的做法最好，符合設計意圖。隨機選偏低，可能代表對新手偏難，待試玩確認。

### v2（Claude 自我迭代，沒有人類評分）

- **背景**：你要求先看我不靠人類評分、自己迭代的結果。所有依據都是本機模擬（`scripts/sim/auto-balance-sim.js`，種子固定可重現），**不代表好不好玩**。
- **事先定義的標準（看結果前訂）**：
  1. 最佳固定組合勝率 ≤ 55%（沒有固定最佳解，對應你的核心設計）
  2. 隨機選勝率 ≥ 30%（新手有機會）
  3. 會讀剋制與倍率的玩家比隨機高 ≥ 25 個百分點（策略有意義）
  4. 平均回合數 4.5 到 6.5
  5. 倍率撞上下限比例 ≤ 10%
- **v1 結果**：通過 3/5。隨機選 20.5%（太低）、平均 6.63 回合（幾乎打滿 7 回合）。
- **改了什麼**：平衡幅度 0.15 改 0.14；電腦對手選單位的隨機度由 0.5–1.5 倍放寬到 0–2 倍。其餘完全不變。
- **為什麼**：掃描 72 組參數。能全過的組合多半把平衡幅度降到 0.10，讓最佳固定組合勝率升到 52–55%，削弱核心設計，所以不採用。0.14 在「沒有固定最佳解」與「新手可玩」之間較均衡。
- **v2 模擬結果**（delta 0.14，兩組種子）：隨機選 28–30%、會讀玩家約 71%、最佳固定組合約 48%、平均 6.5 回合、倍率幾乎不撞邊界、讀倍率玩家每場平均換 4.2 種組合。
- **假設**：v2 比 v1 更像「沒有固定最佳解，但新手仍有機會贏」。
- **已知限制，請別把它當成進步的證據**：
  - 隨機選勝率有一部分是靠「讓電腦更笨」換來的，不是遊戲設計變好。真人若覺得對手太好打，這項就沒有價值。
  - 平均 6.5 回合偏長（上限 7），v2 仍沒有解決；可能是下一個迭代點。
  - 沒有量到手感、節奏、成就感，這些必須靠真人評分。
