# 點子收件箱

點子分成三層，各自存放在對應目錄，處理方式與自由度不同。

## 三層分類

| 層級 | 形式 | 存放位置 | 預設處理方式 |
|---|---|---|---|
| A. 關鍵詞 | 幾個詞 | `keywords.md` | Claude 可自由發想，也可以捨棄 |
| B. 一句話點子 | 一兩句描述 | `seeds/<id>.md` | 保留核心，其餘由 Claude 補完，並標註決定歸屬 |
| C. 玩法草稿 | 有明確規則的初稿 | `drafts/<id>.md` | 玩法規則忠實實作，不因低分自動迭代 |

## 面向自由度

同一個點子的不同面向可以有不同自由度。每個點子檔都要填寫面向自由度表。

| 面向 | 說明 | 可選值 |
|---|---|---|
| 玩法規則 | 操作、勝負、數值 | `locked`（鎖定）／`partial`（部分可補）／`free`（可自由發想） |
| 關卡與內容 | 關卡配置、文字 | 同上 |
| 美術 | 配色、角色風格 | 同上 |
| 音樂與音效 | 配樂、音效 | 同上 |
| UI/UX | 介面排版、操作回饋 | 同上 |

C 層點子的玩法規則通常為 `locked`，但美術、音樂與 UI/UX 可以是 `free` 並自動迭代。

## 狀態

`未處理` → `實作中` → `已試玩` → `已擱置`

## 決策紀錄格式

每個點子檔底部要有決策紀錄，每筆記錄包含日期、面向、決定內容與決定者。

決定者只能是：
- `你`：來自你的原始輸入
- `Claude`：Claude 為補完內容而做的決定
- `評分回饋`：依據人類評分所做的調整

## 不同層級的處理規則

- **A 層**：Claude 可以自由發想，產生的點子若要進一步發展，需轉為 B 層並保留來源關鍵詞。
- **B 層**：Claude 不得改寫你明確指定的核心設定；對未指定的部分可以補完，但每一項都要記錄。
- **C 層**：`locked` 的玩法規則不得由 Claude 修改。若對玩法有疑慮，只能在 `open-questions.md` 提出，由你決定。
